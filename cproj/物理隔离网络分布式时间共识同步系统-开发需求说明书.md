## 1. 编写目的与读者

### 1.1 编写目的

规定「物理隔离网络分布式时间共识同步系统」的**唯一开发需求基线**（合并算法汇报稿、工程 EDRS 与报文—状态机对齐结论），使研发、测试、集成与验收在同一标准下工作。覆盖：

1. 系统组成、约束与能力边界（含精同步 / 宽同步分层）；
2. Agent 三层软件架构、有限状态机与七步闭环；
3. TSYN 自定义报文（Type `0x01`～`0x08`）、签名与时延测量；**状态机—报文一一对照**；
4. 中位数共识、滑动窗口漂移拟合与合成时钟输出；
5. **管控面**：Agent 上报、配置下发、告警审计、控制台；
6. **NTP 网关与异构接入**：交换机 / 摄像机等宽同步覆盖；
7. 专利源材料冲突消解与工程定稿（OC）；
8. 性能宣称指标、部署环境与验收条目。

## 2. 术语、符号与约定

### 2.1 术语

| 术语 | 含义 |
|------|------|
| 本地逻辑时钟 \(C_i(t)\) | 节点 \(i\) 由 OS 暴露的单调计数器（`CLOCK_MONOTONIC`） |
| 共识时间 \(T_c\) | 本轮有效采样中位数聚合得到的网内虚拟时间基准 |
| 合成时钟 \(T_{i,\mathrm{syn}}(t)\) | 经偏移/漂移校正后对外输出的统一时间 |
| 精同步层 | 安装共识 Agent 的节点集群，P2P 达成 \(T_c\) 并输出合成时钟 |
| 宽同步层 | 通过 NTP/SNTP 接入的交换机、摄像机等异构设备 |
| 管控面 | Agent↔Server 的配置与状态通道，不影响授时精度路径 |
| 数据面 | Agent 间共识 UDP 通信，影响授时精度 |
| Time Control Server | 管控服务端：汇聚、告警、审计、配置下发、控制台 |
| NTP 网关 | 消费合成时钟、对外提供标准 NTP/SNTP（UDP 123）的出口节点 |
| Reporter | Agent 内置采集与上报模块，与共识热路径解耦 |
| Ext_Sync | 可选：将共识时钟与外部/人工基准一次性对齐 |
| Dmax | 单向传输时延工程上界（默认 10ms） |
| \(n\) / \(f\) | 共识节点总数 / 最大可容忍故障节点数，须 \(n \geq 3f+1\) |
| TSYN | 协议 Magic：`0x5453594E`（ASCII `"TSYN"`） |
| Round | 同步轮次编号 |
| PeerFault | 对端故障嫌疑/确认：检测方**不**进入本机 Fault |
| LocalFault | 本机故障：仅故障节点进入 Fault → Recovering |

### 2.2 符号表（源自 S2/S4）

| 符号 | 说明 |
|------|------|
| \(t\) | 真实物理时间 |
| \(C_i(t)\) | 节点 \(i\) 本地单调逻辑时钟 |
| \(\alpha_i\) / \(\hat{\alpha}_i\) | 真实漂移率 / 估计漂移率 |
| \(\beta_i\) / \(\hat{\beta}_i\) | 真实偏移 / 估计偏移 |
| \(T_0,T_1,T_2,T_3\) | 双向时延四元时间戳 |
| \(\mathrm{RTT}_{ij}\) | 往返时延 |
| \(\hat{\theta}_{ij}\) | 单次观测时钟偏移 |
| \(L\) | 滑动窗口长度（默认 10） |
| \(T\) | 同步周期（默认 1s，可自适应） |
| \(\Delta t\) | 距上次同步的本地逻辑时长 |
| \(\varepsilon_{\max}\) | 采样偏差稳定判定阈值 |

| 参数 | 默认值 | 说明 |
|------|--------|------|

## 3. 建设目标与问题边界

### 3.1 业务背景（S1）

在工业闭环、水下、矿井、屏蔽机房、涉密内网等**完全物理隔离**环境中，存在：

- 无法或不允许接入 GPS / 北斗 / PPS / 互联网 NTP；
- 未配备 OCXO、原子钟、IEEE 1588 硬件时间戳网卡；
- 仍需全网统一时序，支撑日志审计、故障溯源、安全审计与业务时序控制；
- 大量交换机、摄像机等设备无法安装共识 Agent，但仍需时间大致一致。

### 3.2 建设目标

| 编号 | 目标 | 说明 |
|------|------|------|
| G1 | 无外部授时 | 不破坏物理隔离，不依赖卫星/外网 NTP |
| G2 | 无守时硬件 | 仅使用主板 RTC / OS 单调钟 |
| G3 | 分布式共识 | 无中心权威，节点对等形成 \(T_c\) |
| G4 | 拜占庭容错 | \(n\geq 3f+1\)，容忍最多 \(f\) 个故障/恶意节点 |
| G5 | 漂移闭环抑制 | 原生 \(>10\mathrm{ppm}\) → 宣称 ≤0.1ppm |
| G6 | 长期相对一致 | 合成时钟单调、相对误差有界、长期不发散 |
| G7 | 可故障恢复 | 检测、剔除、静默对齐、重入同步 |
| G8 | 异构覆盖 | 服务器走 Agent 共识；交换机/摄像机走 NTP 对时 |
| G9 | 可运维 | Agent 主动上报；管控汇聚、告警、配置下发与审计 |
| G10 | 报文—状态机一致 | 每条依赖通信的状态转移均有确定报文格式与验收条件 |

### 3.3 问题边界（必须明确）

| 编号 | 边界 |
|------|------|
| B1 | 输出默认为**网内虚拟时间**，不等于 UTC；对齐真实时间须 Ext_Sync / 人工单向基准 |
| B2 | 精度分层：Agent 亚毫秒～毫秒级相对一致；NTP 客户端毫秒～百毫秒级 |
| B3 | ≤0.3ms / ≤0.1ppm 等为**宣称值**，合同验收值须 PoC 实测固化 |
| B4 | 不适用：必须直接溯源 UTC、允许卫星授时、追求微秒级硬件同步的场景 |
| B5 | 管控 Server **不参与**共识、**不替代** NTP 出口；Server 宕机不得中断共识与 NTP 服务 |

## 4. 系统总体架构需求

### 4.1 系统组成（V1.1 扩展）

| 组件 | 部署位置 | 技术选型（建议） | 职责 |
|------|----------|------------------|------|
| 共识 Agent | Linux 服务器 / 工控机 / VM | C（或等价）；可选 Go | P2P 共识、漂移估计、合成时钟；Reporter 上报 |
| 管控服务端（Time Control Server） | 独立 VM 或兼岗 | gRPC + HTTP | 汇聚、告警、审计、配置下发、控制台 |
| NTP 网关 | NUC 或共识节点兼岗 | chrony + time-shim | 向异构设备提供 NTP/SNTP |
| 宽同步采集器（可选） | Server 侧 | SNMP / ONVIF | 采集交换机/摄像机时间偏差 |

算法源材料中的「节点 + 通信链路 + 共识同步模块」对应上表**精同步层**；V1.1 增加管控层与时间出口/宽同步层。

### 4.2 逻辑架构

```
┌──────────────────────────────────────────────────────────────────┐
│                    管控层（Time Control Server）                    │
│         配置与密钥 │ 状态汇聚 │ 告警审计 │ Web 控制台              │
└──────────────▲───────────────────────────┬───────────────────────┘
               │ gRPC/HTTPS 上报            │ 配置/指令下发
┌──────────────┼───────────────────────────┼───────────────────────┐
│              │     精同步层（共识 Agent）  │                       │
│  Agent 1 ◄──► Agent 2 ◄──► … ◄──► Agent N   （UDP 47500 / TSYN） │
│              │  get_synced_time()         │                       │
└──────────────┼───────────────────────────┘                       │
               ▼
┌──────────────────────────────────────────────────────────────────┐
│              时间出口层（NTP 网关，主备） chrony + 合成时钟          │
└───────────────────────────────┬──────────────────────────────────┘
                                ▼ UDP 123
┌──────────────────────────────────────────────────────────────────┐
│         宽同步层：交换机 / 路由器 / 防火墙 / 网络摄像机 …           │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 管控面与数据面分离

| 平面 | 协议 | 是否影响授时精度 | 要求 |
|------|------|------------------|------|
| 数据面 | Agent 间 UDP 47500 | 是 | 低延迟、高优先级；与管控解耦 |
| 管控面 | Agent → Server gRPC/HTTPS | 否 | 允许秒级延迟；Server 宕机不影响共识 |

**FR-ARCH-001（P0）**：系统须满足物理隔离、无外部授时、无 OCXO/原子钟/1588 网卡、仅用漂移本地逻辑时钟、分布式无中心、\(n\geq 3f+1\)。  
**FR-ARCH-002（P0）**：管控服务端不得参与 P2P 时间共识，不得修改 \(T_c\)。  
**FR-ARCH-003（P0）**：Agent 须使用本地缓存配置在 Server 不可达时继续共识；恢复后自动补报。  
**FR-ARCH-004（P0）**：Reporter / 管控 I/O **禁止**在 UDP 共识热路径发起阻塞的 HTTP/gRPC 调用。

### 4.4 Agent 软件分层（S1/S3/S5）

| 层级 | 名称 | 职责 |
|------|------|------|
| L1 | 本地逻辑时钟层 | 提供单调 \(C_i(t)\)；线性漂移模型 |
| L2 | 分布式时间共识层 | 周期采样；中位数 \(T_c\)；容错确认 |
| L3 | 时钟合成与漂移校正层 | T0～T3；滑动窗口回归；输出 \(T_{i,\mathrm{syn}}\) |
| L4 | 应用 / 运维输出层 | `get_synced_time()`；Reporter；Ext_Sync |

**FR-ARCH-005（P0）**：L1～L3 解耦；L4 不得反向改写共识热路径状态。

### 4.5 信息流转（S2/S5 图2）

1. L1 产生瞬时时间戳 \(C_i(t)\)；
2. 节点间 TIME_REQ/TIME_RESP 交换并完成时延测量；
3. 由 \(T_0\sim T_3\) 计算 RTT 与 \(\hat{\theta}\)，多轮形成观测序列；
4. 滑动窗口拟合得到 \(\hat{\alpha},\hat{\beta}\)；
5. 合成并输出 \(T_{i,\mathrm{syn}}(t)=C_i(t)+\hat{\beta}_i+\hat{\alpha}_i\cdot\Delta t\)；
6. （V1.1）Reporter 快照上报管控面；NTP 网关消费合成时间对外服务。

### 4.6 推荐部署规模

| 规模 | Agent \(n\) | \(f\) | NTP 网关 |
|------|-------------|-------|----------|
| 最小可用 | 3 | 0～1 | 1（建议 2） |
| **推荐生产** | **5** | **1** | **2 台主备** |
| 大型网络 | 7～9 | 2 | 2 + 按区域分区 |

节点角色配置须支持：`consensus_only`（纯共识）/ `gateway`（兼 NTP 出口）。

## 5. 功能开发需求

### 5.1 本地逻辑时钟（FR-CLK）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-CLK-001 | P0 | 仅使用 `CLOCK_MONOTONIC`（或等价单调源）作为采样与合成基础 |
| FR-CLK-002 | P0 | **纯共识节点**须禁用 NTPd/Chrony 等对系统墙钟的外部对时；**兼 NTP 网关节点**允许 chrony/shim **仅消费本机合成时间**对外服务，禁止从外网/外源取时 |
| FR-CLK-003 | P0 | 满足严格单调：\(\forall t_1<t_2,\ C_i(t_1)<C_i(t_2)\) |
| FR-CLK-004 | P0 | 按线性模型建模：\(C_i(t)=C_{i,0}+(1+\alpha_i)\,t+\beta_i\) |
| FR-CLK-005 | P1 | 时间戳读取优先走 vDSO 用户态路径 |

### 5.2 采样与双向时延测量（FR-MEAS）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-MEAS-001 | P0 | TimerTick 后向其余节点发送 TIME_REQ，记录 \(T_0=C_i(t_0)\) |
| FR-MEAS-002 | P0 | 对端记录 \(T_1\)，立即构造 TIME_RESP 填入 \(T_2\) 并回复 |
| FR-MEAS-003 | P0 | 本端收响应记录 \(T_3\)，构建四元时间戳样本 |
| FR-MEAS-004 | P0 | \(\mathrm{RTT}=(T_3-T_0)-(T_2-T_1)\)，\(\hat{\theta}=\dfrac{T_1+T_2}{2}-\dfrac{T_0+T_3}{2}\) |
| FR-MEAS-005 | P0 | 有效性：RTT≥0 且 RTT≤2×Dmax；否则丢弃 |
| FR-MEAS-006 | P0 | CollectTimeout=2×Dmax+δ（默认 22ms）；超时标记邻居疑似故障，样本不参与本轮中位数 |

### 5.3 分布式时间共识（FR-CNS）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-CNS-001 | P0 | 对本轮有效采样升序排序，取中位数作为 \(T_c\) |
| FR-CNS-002 | P0 | 故障节点数 \(<n/3\) 时抑制异常采样 |
| FR-CNS-003 | P0 | 广播 CONSENSUS_RESULT；收到 ≥2f+1 确认后 ConsensusDone |
| FR-CNS-004 | P0 | 运行期无长期中心权威；启动允许最小 NodeID 临时 Leader 广播 START_SYNC |
| FR-CNS-005 | P0 | 有效样本不足 2f+1 时**不更新** \(T_c\)；连续失败达阈值走故障处理 |
| FR-CNS-006 | P1 | 初始/恢复阶段完整 3 轮多层共识 |
| FR-CNS-007 | P1 | 稳态轻量 2 轮二阶共识 |
| FR-CNS-008 | P1 | 周期自适应；正常节点不足 \(n\geq 3f+1\) 时告警等待重建 |

### 5.4 漂移估计与合成时钟（FR-SYN）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-SYN-001 | P0 | 长度 \(L\)（默认 10）滑动窗口 + 最小二乘，估计 \(\hat{\alpha}_i,\hat{\beta}_i\) |
| FR-SYN-002 | P0 | \(T_{i,\mathrm{syn}}(t)=C_i(t)+\hat{\beta}_i+\hat{\alpha}_i\cdot\Delta t\) |
| FR-SYN-003 | P0 | 合成时钟严格单调；必要时钳位/最小步进 |
| FR-SYN-004 | P0 | \(\hat{\alpha}/\hat{\beta}\) 更新限幅 |
| FR-SYN-005 | P0 | `get_synced_time()` 输出合成时间；默认**不修改**业务墙钟（网关例外见 FR-NTP） |
| FR-SYN-006 | P1 | Ext_Sync：单向网闸/光学图像等一次性校准，完成后返回 SyncWait |

### 5.5 故障容错与恢复（FR-FLT）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-FLT-001 | P0 | 超时 → PeerFaultSuspect；检测方**不**进本机 Fault |
| FR-FLT-002 | P0 | 连续 3 轮无响应 → PeerFaultConfirm，广播 FAULT_NOTIFY |
| FR-FLT-003 | P0 | ≥f+1 相同 FaultNodeID 经验签后逻辑剔除 |
| FR-FLT-004 | P0 | 剩余节点仍满足 \(n\geq 3f+1\) 时共识不中断 |
| FR-FLT-005 | P0 | 故障节点本机进 Fault；恢复后 Recovering：静默 ≥2 周期 |
| FR-FLT-006 | P0 | 中位数求 \(T_{c,\mathrm{target}}\)，修正模型，广播 RECOVER_ANNOUNCE |
| FR-FLT-007 | P0 | ≥2f+1 RECOVER_ACK 后 AlignSyncDone，重入 SyncWait |
| FR-FLT-008 | P1 | Reason 支持超时、错误值；可扩展签名失败累计、人工标记 |

> **工程澄清**：`FaultDetect` 拆分为 PeerFault\* 与 LocalFaultDetect。

### 5.6 报文安全（FR-SEC）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-SEC-001 | P0 | 共识报文：16B Header + Payload + **64B** ECDSA-P256 Signature |
| FR-SEC-002 | P0 | 签名输入 `Header ‖ Payload`；验签失败丢弃并记事件 |
| FR-SEC-003 | P0 | 强制验签：START_SYNC、CONSENSUS_RESULT、FAULT_NOTIFY、RECOVER_ANNOUNCE |
| FR-SEC-004 | P0 | 默认亦验签 TIME_REQ/RESP/ACK；可配置关闭非强制类，但不得省略 Signature 字段 |
| FR-SEC-005 | P0 | UDP 47500；与 NTP 123、PTP 319/320 分离；建议 `SO_PRIORITY=7` |
| FR-SEC-006 | P0 | Type：0x01～0x08（FAULT_NOTIFY=**0x06**） |
| FR-SEC-007 | P0 | 未在公钥/NodeID 白名单内拒绝加入共识 |
| FR-SEC-008 | P1 | 共识密钥与管控 mTLS 证书分开管理；建议可轮换 |
| FR-SEC-009 | P1 | Agent↔Server 采用 mTLS 或 Token + IP 白名单 |

### 5.7 管控与上报（FR-CTL）（V1.1 新增）

| 编号 | 优先级 | 需求描述 |
|------|--------|----------|
| FR-CTL-001 | P0 | Agent 内置 Reporter，独立于共识热路径（独立线程/协程），无锁快照读取共识状态 |
| FR-CTL-002 | P0 | 上报至少含：节点身份、运行配置、α̂/β̂、monotonic_ns、synced_ns、consensus_tc、round、fsm_state、质量指标、邻居观测 |
| FR-CTL-003 | P0 | 上报类型：Heartbeat（默认 10s）、Metrics（默认 1s 可配）、ConfigSnapshot（启动/变更）、Event（即时） |
| FR-CTL-004 | P0 | Agent→Server 主推 gRPC（50051），HTTPS POST 备选；`node_id + seq` 幂等去重 |
| FR-CTL-005 | P0 | Server 配置版本管理与下发；Agent 回传 ConfigAck（成功/失败） |
| FR-CTL-006 | P0 | Server **不做**：参与共识、替代 NTP 出口、要求 Agent 在线才能共识 |
| FR-CTL-007 | P1 | 控制台：全网概览、节点详情曲线、共识拓扑、配置管理、事件审计、宽同步设备 |

| FR-CTL-010 | P1 | 数据保留：Metrics 7 天；心跳 3 天；事件与审计 1 年；配置版本永久 |

配置热更新范围：

## 6. 状态机与流程开发需求

### 6.1 状态集合（S1/S4/S5）

| 状态 | 说明 |
|------|------|
| Init | 初始化 |
| SyncWait | 同步等待 |
| Collecting | 采样收集 |
| Consensus | 共识计算 |
| Estimating | 漂移估计 |
| Running | 正常运行（对外提供合成时间） |
| Fault | 本机故障 |
| Recovering | 故障恢复 |
| Stopped | 停止 |
| Ext_Sync | 外部单向校时（扩展） |

### 6.2 合法转移与事件（FR-FSM）

| 转移 | 触发事件 | 优先级 |
|------|----------|--------|
| Init → SyncWait | Start | P0 |
| SyncWait → Collecting | TimerTick | P0 |
| Collecting → Consensus | CollectDone | P0 |
| Consensus → Estimating | ConsensusDone | P0 |
| Estimating → Running | EstimateDone | P0 |
| Running → SyncWait | TimerTick | P0 |
| 任意 → Fault | LocalFaultDetect | P0 |
| Fault → Recovering | RecoverDone | P0 |
| Recovering → SyncWait | AlignSyncDone | P0 |
| Running → Stopped | Stop | P0 |
| Stopped / Fault → SyncWait | Reset | P0 |
| SyncWait → Ext_Sync | ExternalTimeValid | P1 |
| Ext_Sync → SyncWait | ExtSyncDone | P1 |

**FR-FSM-001（P0）**：非法转移不得改变当前状态，并记录错误事件。  
**FR-FSM-002（P0）**：PeerFaultSuspect / PeerFaultConfirm **不**导致本机进入 Fault。  
**FR-FSM-003（P1）**：Ext_Sync 须产生可审计事件（经管控面可查）。  
**FR-FSM-004（P0）**：实现须满足 §6.3 状态机—报文对照表；缺报文类型或类型冲突视为不满足协议基线。

### 6.3 状态机—报文完整对照（强制，来自对齐报告 / DRS）

| 状态转移 / 场景 | 触发事件 | 报文 / 接口 | 覆盖说明 |
|-----------------|----------|-------------|----------|
| Init→SyncWait | Start | START_SYNC(0x01) | 临时 Leader 广播；验签后进入 SyncWait |
| SyncWait→Collecting | TimerTick | 无网络报文 | 本地定时器 |
| Collecting 内 | 采样交换 | TIME_REQ(0x02)/TIME_RESP(0x03) | 获取 T0～T3；超时→PeerFaultSuspect |
| Collecting→Consensus | CollectDone | 无（本地） | 收齐或超时结束收集 |
| Consensus 内 | 广播/确认 | CONSENSUS_RESULT(0x04)/CONSENSUS_ACK(0x07) | ≥2f+1 ACK → ConsensusDone |
| Consensus→Estimating | ConsensusDone | 无（本地） | — |
| Estimating→Running | EstimateDone | 无（本地） | 滑动窗口拟合 |
| Running→SyncWait | TimerTick | 无网络报文 | Round++ |
| 对端故障确认 | PeerFaultConfirm | FAULT_NOTIFY(**0x06**) | ≥f+1 后逻辑剔除；检测方保持主闭环 |
| （故障节点）→Fault | LocalFaultDetect | 可收 FAULT_NOTIFY | **仅**本机故障节点进入 Fault |
| Fault→Recovering | RecoverDone | 无（链路恢复） | — |
| Recovering 内 | 对齐准备 | 监听 RESULT/RESP；发 RECOVER_ANNOUNCE(0x05) | 静默≥2 周期 |
| Recovering→SyncWait | AlignSyncDone | RECOVER_ACK(0x08) | ≥2f+1 ACK 后重入 |
| SyncWait↔Ext_Sync | ExternalTimeValid / ExtSyncDone | 本地 EXT_TIME_IN 帧 | 不占用 P2P Type 空间 |
| Running→Stopped | Stop | 无网络报文 | — |

> 专利 V3 实施例曾缺 TIME_*/CONSENSUS_ACK/RECOVER_ACK 完整格式表，并将 FAULT 误标为 0x03；工程实现**必须以本表与 §7 / §12 为准**。

### 6.4 单轮闭环时序（T=1s）

1. SyncWait 等待高精度定时器；
2. TimerTick → Collecting：并发 TIME_REQ，Timeout=22ms；
3. CollectDone → Consensus：中位数 \(T_c\)，等待 ≥2f+1 CONSENSUS_ACK；
4. ConsensusDone → Estimating：滑动窗口回归；
5. EstimateDone → Running：可读合成时间；Reporter 可快照上报；
6. 下一 TimerTick → SyncWait，Round++。

### 6.5 故障与恢复流程

故障注入检测 → 疑似 → 连续 3 轮确认 → FAULT_NOTIFY → ≥f+1 剔除 → 静默监听 → 模型修正 → RECOVER_ANNOUNCE → ≥2f+1 ACK → 重入。关键事件须上报管控面。

| 项目 | 宣称值 |
|------|--------|
| 故障检测时间 | ≤3.02s |
| 故障剔除共识时间 | ≤0.5s |
| 故障节点恢复时间 | ≤2.5s |
| 恢复后首次同步误差 | ≤0.15ms |
| 恢复后第 5 轮同步误差 | ≤0.05ms |

## 7. 通信协议与报文开发需求

### 7.1 传输与公共约定（IF-TSYN）

| 项目 | 定稿值 |
|------|--------|
| 传输 | UDP |
| 默认端口 | 47500 |
| 网络优先级 | 建议 `SO_PRIORITY=7` |
| 公共结构 | Header(16B) + Payload + Signature(64B) |
| Magic | `0x5453594E`（"TSYN"） |
| Version | `0x02` |
| 字节序 | 大端 |
| 时间戳单位 | ns（uint64） |

**Header（16 字节）**：

| 偏移 | 字段 | 长度 | 说明 |
|------|------|------|------|
| 0 | Magic | 4B | 0x5453594E |
| 4 | Version | 1B | 0x02 |
| 5 | Type | 1B | 见报文类型表 |
| 6 | Flags | 1B | Bit1=URGENT（FAULT_NOTIFY） |
| 7 | Reserved | 1B | 0 |
| 8 | SenderID | 2B | 发送节点 ID |
| 10 | PayloadLen | 2B | Payload 长度 |
| 12 | Round | 4B | 同步轮次 |

签名输入：`Header ‖ Payload`（见 §12）。

### 7.2 报文类型（定稿）

| Type | 名称 | 强制验签 | 主要关联状态 | 说明 |
|------|------|----------|--------------|------|
| 0x01 | START_SYNC | 是 | Init→SyncWait | 启动/重启同步 |
| 0x02 | TIME_REQ | 默认是（可配） | Collecting | 时间采样请求 |
| 0x03 | TIME_RESP | 默认是（可配） | Collecting | 含 T0/T1/T2；接收方记 T3 |
| 0x04 | CONSENSUS_RESULT | 是 | Consensus；Recovering 监听 | 广播本轮 \(T_c\) |
| 0x05 | RECOVER_ANNOUNCE | 是 | Recovering | 恢复宣告 |
| **0x06** | **FAULT_NOTIFY** | 是 | 对端故障确认 | **禁止使用 0x03** |
| 0x07 | CONSENSUS_ACK | 默认是（可配） | Consensus→Estimating | 共识确认 |
| 0x08 | RECOVER_ACK | 默认是（可配） | Recovering→SyncWait | 恢复确认 |

### 7.3 关键 Payload

#### START_SYNC（0x01）

| 字段 | 长度 | 说明 |
|------|------|------|
| LeaderID | 2B | 临时 Leader |
| PeriodMs | 4B | T（ms），默认 1000 |
| DmaxMs | 4B | 默认 10 |
| StartRound | 4B | 起始轮次 |

#### TIME_REQ（0x02）

| 字段 | 长度 | 说明 |
|------|------|------|
| RequestID | 4B | Round 内序号 |
| T0 | 8B | 发送方单调钟（ns） |

#### TIME_RESP（0x03）

| 字段 | 长度 | 说明 |
|------|------|------|
| RequestID | 4B | 对应请求 |
| ResponderID | 2B | 响应节点 |
| Reserved | 2B | 0 |
| T0 / T1 / T2 | 各 8B | 回显与对端戳 |

#### CONSENSUS_RESULT（0x04）

| 字段 | 长度 | 说明 |
|------|------|------|
| Tc | 8B | 共识基准（ns） |
| SampleCount | 2B | 样本数 |
| Reserved | 2B | 0 |
| VoteBitmap | 变长可选 | 初始多层共识二阶可携带认可位图；稳态可省略 |

#### CONSENSUS_ACK（0x07）

| 字段 | 长度 | 说明 |
|------|------|------|
| Tc | 8B | 确认的共识基准 |
| Agree | 1B | 1=认可，0=拒绝 |
| Reserved | 3B | 0 |

#### FAULT_NOTIFY（0x06）

| 字段 | 长度 | 说明 |
|------|------|------|
| FaultNodeID | 2B | 故障节点 |
| Reason | 1B | 0x01 超时；0x02 错误值；0x03 签名失败累计；0x04 人工 |
| Reserved | 1B | 0 |
| DetectRound | 4B | 检测轮次 |

#### RECOVER_ANNOUNCE（0x05）

| 字段 | 长度 | 说明 |
|------|------|------|
| NodeID | 2B | 恢复节点 |
| Reserved | 2B | 0 |
| BetaNs | 8B | \(\hat{\beta}\)（ns） |
| AlphaPpm | 8B | 线格式见 DR-001 / IF-TSYN-015 |
| TargetTc | 8B | 对齐目标 |

#### RECOVER_ACK（0x08）

| 字段 | 长度 | 说明 |
|------|------|------|
| NodeID | 2B | 被确认的恢复节点 |
| Accept | 1B | 1=接受重入，0=拒绝 |
| Reserved | 1B | 0 |

### 7.4 Ext_Sync 本地单向接口帧（非 P2P Type）

外部时间接口为单向传入（单向网闸、光学图像等），**不占用** `0x01`～`0x08`。建议本地 EXT_TIME_IN 帧：

| 字段 | 长度 | 说明 |
|------|------|------|
| Magic | 4B | 0x45585449（"EXTI"） |
| UtcNs | 8B | 外部时间（ns） |
| Source | 1B | 0x01 网闸；0x02 光学；0x03 人工核准 |
| Reserved | 3B | 0 |
| AuthTag | 变长 | 鉴权/审计标签 |

### 7.5 数据与量纲（DR）

| 编号 | 优先级 | 需求 |
|------|--------|------|
| DR-001 | P0 | 内部 \(\hat{\alpha}\) 无量纲；线格式 AlphaPpm=`ppm×10⁶` 有符号整数，须有编解码换算（例：0.047ppm → 47000） |
| DR-002 | P0 | 时间相关字段统一 ns |
| DR-003 | P0 | Agent 配置：NodeID、邻居列表、\(n/f\)、T、L、Dmax、密钥、端口、角色、`server_endpoint` |
| DR-004 | P1 | 热更新 T/L/Dmax/故障阈值/上报周期；邻居列表滚动重启 |
| DR-005 | P0 | Server 维护公钥白名单、配置版本、告警规则 |
| DR-006 | P1 | 存储保留期按 FR-CTL-010 |

**IF-TSYN-015（定稿）**：`alpha_fraction = (AlphaPpm / 1e6) × 1e-6`；禁止把 `AlphaPpm` 原值直接乘 \(\Delta t\)。

## 8. 算法实现需求

### 8.1 中位数共识

**FR-ALG-001（P0）**：对有效采样排序取中位数为 \(T_c\)。  
**FR-ALG-002（P0）**：样本须先经时延修正 / 有效性过滤。

### 8.2 最小二乘漂移拟合

**FR-ALG-003（P0）**：窗口满 \(L\) 后拟合；未满策略固定并文档化。  
**FR-ALG-004（P1）**：估计值随轮次收敛可测。

### 8.3 安全与活性性质

| 性质 | 工程含义 |
|------|----------|
| 安全性 | 正确节点合成时间差最终有界；严格单调；错误节点无法破坏共识 |
| 活跃性 | 连通且多数节点正常时共识持续推进 |
| 稳定性 | 相对误差 \(\leq 2(D_{\max}+\varepsilon_{\max})\)，不随时间发散 |

### 8.4 多层共识与报文映射（对齐权利要求 / DRS）

| 阶段 | 共识阶 | 交互目的 | 报文 |
|------|--------|----------|------|
| 初始 | 一阶 | 交换采样 | TIME_REQ / TIME_RESP |
| 初始 | 二阶 | 广播认可倾向 | CONSENSUS_RESULT（可带 VoteBitmap） |
| 初始 | 三阶 | 确认全网一致 | CONSENSUS_ACK ≥2f+1 |
| 稳态 | 一阶轻量 | 快速交换采样 | TIME_REQ / TIME_RESP |
| 稳态 | 二阶轻量 | 确认并得到 \(T_c\) | CONSENSUS_RESULT + CONSENSUS_ACK |

### 8.5 同步周期自适应（P1）

- 稳定判定：连续 3 轮满足「≥2f+1 节点达成共识 + 采样偏差≤\(\varepsilon_{\max}\)」；
- 稳定态：适度拉长 \(T\)；不稳定态：缩短 \(T\)；
- 故障超限：正常节点数不满足 \(n\geq 3f+1\) 时告警并等待重建。

### 9.4 实现示意（非强制代码形态）

```c
uint64_t get_synced_time(void) {
    uint64_t C_now = /* clock_gettime(CLOCK_MONOTONIC) → ns */;
    uint64_t C_last = get_last_sync_C();
    uint64_t delta_t = C_now - C_last;
    return C_now + beta_hat + (uint64_t)(alpha_hat * (double)delta_t);
}
```

## 12. 冲突消解与工程定稿

> 本节吸收《专利报文与状态机对齐检查报告》结论，作为实现与验收的裁决依据。

### 12.1 专利示例主要缺陷（已消解）

| 维度 | 原结论 | 工程处置 |
|------|--------|----------|
| 状态机覆盖 | TIME_*/ACK 格式缺失；多层共识无 Type | §6.3 / §7 / §8.4 强制补齐 |
| 格式合理性 | FAULT=0x03 冲突；Signature=32B；公共头不统一 | OC-01～03 |
| 状态机语义 | 邻居超时易误读为本机 Fault | OC-04；PeerFault / LocalFault |

### 12.2 定稿表（OC）

| 编号 | 冲突点 | 源材料表述 | 工程定稿 | 理由 |
|------|--------|------------|----------|------|
| OC-01 | Signature 长度 | 多处写 32B | **64B（r‖s）** | ECDSA-P256 定长编码 |
| OC-02 | FAULT_NOTIFY Type | 示例写 0x03 | **0x06** | 0x03 已分配 TIME_RESP |
| OC-03 | 公共头字段 | 示例不统一 | **16B Header** | 可扩展、可解析 |
| OC-04 | FaultDetect | 任意状态→Fault | **PeerFault\* / LocalFaultDetect** | 避免邻居超时误杀本机 |
| OC-05 | 签名覆盖 | 强调若干报文 | **全类型带 Signature；关键强制验签** | 安全基线一致 |
| OC-06 | 兼岗节点对时 | 一律禁用 Chrony | **gateway 角色可消费合成时间对外 NTP** | 支撑异构覆盖，禁止外源取时 |
| OC-07 | 多层共识报文 | 仅有文字无 Type | **TIME_* / RESULT / ACK 映射** | 与 Collecting→Consensus 一致 |
| OC-08 | Ext_Sync | 无网络/接口帧 | **本地 EXT_TIME_IN** | 不占用 P2P Type 空间 |
