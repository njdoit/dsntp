## 1. 结论摘要

| 维度 | 结论 |
|------|------|
| 是否全部覆盖状态机 | **否**。主闭环缺 `TIME_REQ/RESP`、`CONSENSUS_RESULT/ACK` 完整格式；恢复缺 `RECOVER_ACK`；多层共识缺报文映射 |
| 报文格式是否合理 | **部分不合理**。公共头不统一；`FAULT_NOTIFY=0x03` 与 `TIME_RESP` 冲突；签名 32B 与 ECDSA-P256 常规编码不符 |
| 是否符合状态机语义 | **基本符合主路径意图，细节有偏差**。邻居超时误写成检测方 `FaultDetect`；`Ext_Sync/Stopped` 无接口说明但可不走网络报文 |

## 2. 状态机 × 报文覆盖矩阵

| 状态 / 转移 | 触发事件 | 应有报文或接口 | V3 现状 | 处置 |
|-------------|----------|----------------|---------|------|
| Init → SyncWait | Start | START_SYNC | 有格式表 | 修正公共头与签名长度 |
| SyncWait → Collecting | TimerTick | 无（本地定时） | OK | — |
| Collecting | 采样 | TIME_REQ / TIME_RESP | 仅文字描述 | **补全格式** |
| Collecting → Consensus | CollectDone | 本地收齐/超时 | OK | 明确超时≠本机 Fault |
| Consensus | 共识广播/确认 | CONSENSUS_RESULT / CONSENSUS_ACK | 仅提 RESULT，ACK 无格式 | **补全** |
| Consensus → Estimating | ConsensusDone | ≥2f+1 ACK | 文字有，格式无 | **补全 ACK** |
| Estimating → Running | EstimateDone | 无（本地拟合） | OK | — |
| Running → SyncWait | TimerTick | 无 | OK | — |
| 对端故障通告 | PeerFaultConfirm | FAULT_NOTIFY | 有，但 Type=0x03 冲突 | **改为 0x06** |
| Fault → Recovering | RecoverDone | 本地/链路恢复 | OK | 区分本机 Fault |
| Recovering | 监听+宣告 | 听 RESULT/RESP；发 ANNOUNCE | ANNOUNCE 有 | — |
| Recovering → SyncWait | AlignSyncDone | RECOVER_ACK ≥2f+1 | 文字有，格式无 | **补全** |
| SyncWait ↔ Ext_Sync | ExternalTimeValid / ExtSyncDone | 本地单向 Ext 帧 | 无 | **补本地接口帧** |
| Running → Stopped / Reset | Stop / Reset | 无网络报文 | OK | — |
| 初始多层共识（权利要求） | 一/二/三阶 | 须映射到报文类型 | 未映射 | **用 0x02～0x04/0x07 映射** |

## 3. 具体缺陷清单

### 3.1 类型码冲突（严重）

- V3 将 `FAULT_NOTIFY` 写成 `Type=0x03`。
- 同一协议中 `TIME_RESP` 必须占用 `0x03`（请求-响应成对）。
- **定稿**：`FAULT_NOTIFY=0x06`。

### 3.2 签名长度不合理

- 多处 `Signature=32B`。
- ECDSA-P256 裸 `r‖s` 为 **64B**；若用 DER 则长度可变，不利于定长 UDP 帧。
- **定稿**：全报文尾部固定 **64B**；签名输入 = `Header ‖ Payload`。

### 3.3 公共头不统一

- `START_SYNC` 含 Version；`FAULT/RECOVER` 示例无 Version/SenderID/PayloadLen。
- **定稿**：统一 16B Header。

### 3.4 缺失格式表

- `TIME_REQ`、`TIME_RESP`、`CONSENSUS_RESULT`、`CONSENSUS_ACK`、`RECOVER_ACK`。

### 3.5 状态机语义偏差

- “邻居 TIME_RESP 超时 → 本机 FaultDetect”易被读成本机进入 Fault。
- **澄清**：检测方发 `FAULT_NOTIFY` 并继续主闭环；**仅故障节点本机**进入 Fault/Recovering。

### 3.6 权利要求多层共识未落报文

- 一阶/二阶/三阶文字存在，但无对应 Type。
- **映射**：一阶=`TIME_REQ/RESP`；二阶=`CONSENSUS_RESULT`；三阶（及稳态确认）=`CONSENSUS_ACK`。

## 4. 定稿 Type 一览（0x01～0x08）

| Type | 名称 | 强制验签 | 主要状态 |
|------|------|----------|----------|
| 0x01 | START_SYNC | 是 | Init |
| 0x02 | TIME_REQ | 默认可配 | Collecting |
| 0x03 | TIME_RESP | 默认可配 | Collecting |
| 0x04 | CONSENSUS_RESULT | 是 | Consensus / Recovering 监听 |
| 0x05 | RECOVER_ANNOUNCE | 是 | Recovering |
| 0x06 | FAULT_NOTIFY | 是 | 对端故障确认 |
| 0x07 | CONSENSUS_ACK | 默认可配 | Consensus |
| 0x08 | RECOVER_ACK | 默认可配 | Recovering |
