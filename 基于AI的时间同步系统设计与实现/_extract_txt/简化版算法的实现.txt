物理隔离网络分布式时间共识同步算法
文件标识
算法名称：物理隔离网络分布式时间共识同步算法
发明名称：一种物理隔离网络的分布式时间共识同步系统及方法
适用场景：工业闭环、水下、矿井、屏蔽机房、涉密内网等完全物理隔离网络；无 GPS / 北斗 / PPS 外部授时源、无 OCXO 恒温晶振 / 原子钟 / 1588 硬件同步网卡，仅使用主板 RTC 原生漂移逻辑时钟
算法类型：分布式容错时间同步算法（拜占庭容错，中位数共识 + 滑动窗口线性回归漂移校正）
版本：V1.0
同步周期基准：T=1s（支持动态自适应调参）
容错约束：节点总数满足n ≥ 3f + 1，最多容忍 f 个故障 / 恶意节点

二、前置约束条件
网络物理隔离，禁止接入任何外部授时源（GPS、北斗、PPS、互联网 NTP）；
全网无高精度守时硬件：无 OCXO、铷原子钟、硬件 1588 网卡；
仅启用操作系统单调时钟CLOCK_MONOTONIC，关闭 NTPd/Chrony，屏蔽实时墙钟接口；
节点硬件时钟原生漂移∣αi​∣>10ppm，无硬件频率稳定机制；
内网 TCP/UDP 自定义轻量协议，消息时延有界；
节点数量满足分布式容错下界n≥3f+1。
三、三层架构整体算法模型
3.1 底层：本地逻辑时钟层
时钟单调性约束：
∀t1​<t2​,Ci​(t1​)<Ci​(t2​)
2. 硬件线性漂移模型：
Ci​(t)=Ci,0​+(1+αi​)⋅t+βi​
Ci,0​：节点初始计时基数；仅操作系统原生计数器输出，无硬件校正能力。
3.2 中层 1：分布式时间共识层（容错核心）
3.2.1 全网采样收集
每周期 T 触发 TimerTick，节点 i 向全网其余节点发送 TIME_REQ 报文，记录发送戳Ti0​=Ci​(t0​)；
对端节点 j 收到请求记录Tj1​=Cj​(t1​)，立即生成 TIME_RESP，填入Tj2​=Cj​(t2​)并回复；
节点 i 接收响应记录Ti3​=Ci​(t3​)，构建全网采样集合S={C1​,C2​,...,Cn​}。
3.2.2 中位数共识计算（拜占庭容错）
将采样集合 S 升序排序；
取排序后中位数作为本轮全网统一虚拟基准Tc​；
容错能力：可过滤小于 n/3 的异常故障节点采样值，单节点异常不破坏共识。
3.2.3 分阶段共识交互逻辑
阶段 1：初始化 / 故障恢复（完整 3 轮多层共识）
第 1 轮一阶共识：全网广播本地时钟采样，各节点收集全部节点原始时间；
第 2 轮二阶共识：全网广播采样校验结果，确认各节点收到合法采样；
第 3 轮全量共识：统计认可计数，被≥2f+1 节点认可的采样值锁定初始Tc​。
阶段 2：稳态运行（轻量 2 轮二阶共识）
第 1 轮：仅广播本地时钟采样，快速同步全网时钟状态；
第 2 轮：校验采样偏差，≥2f+1 节点认可即达成共识，直接计算Tc​，减少通信开销。
3.2.4 同步周期动态自适应算法
稳定判定条件：连续 3 轮满足「≥2f+1 节点达成共识 + 采样偏差≤εmax​」；
稳定态：拉长同步周期 T，降低网络报文开销；
不稳定态：缩短同步周期 T，提高校正频率抑制漂移发散；
故障超限：正常节点数量不满足n≥3f+1时触发系统告警，等待节点恢复后重建共识。
3.3 中层 2：分布式时钟合成与漂移校正层
3.3.1 双向时延测量算法
RTTij​θ^ij​​=(Ti3​−Ti0​)−(Tj2​−Tj1​)=2Tj1​+Tj2​​−2Ti0​+Ti3​​​​
RTTij​：往返总时延；θ^ij​：扣除传输延迟后的节点间原始观测偏移。
3.3.2 滑动窗口线性回归漂移拟合
维护长度 L 滑动窗口，存储连续 L 轮观测偏移序列{θ^1​,θ^2​,...,θ^L​}；
使用最小二乘法拟合线性模型，输出收敛估计值α^i​（漂移率）、β^​i​（静态偏移）；
迭代收敛特性：同步轮次越多，α^i​→αi​、β^​i​→βi​；
漂移抑制效果：原生＞10ppm 硬件漂移经软件闭环校正收敛至≤0.1ppm。
3.3.3 合成时钟输出公式
Ti,syn​(t)=Ci​(t)+β^​i​+α^i​⋅Δt
Δt=Ci​(t)−Ci,last​：距离上一轮同步的本地计时时长；
输出特性：严格单调递增、全网相对误差有界、长期运行不发散。
3.4 上层：应用输出接口
统一接口get_synced_time()，对外输出Ti,syn​(t)，用于日志审计、故障溯源、业务时序控制；支持可选单向外部时间校准接口（网闸单向输入 UTC 时间一次性校准）。
四、全流程主算法（7 步标准执行流程）
S1 系统初始化
部署 n 个节点，满足n≥3f+1；
关闭 NTP、Chrony，屏蔽 CLOCK_REALTIME，仅启用 CLOCK_MONOTONIC；
配置 Linux 实时内核隔离 CPU 核心，同步进程绑定 SCHED_FIFO 最高优先级；
所有节点进入 Init 初始化状态，加载共识同步模块；
全网广播 START_SYNC 签名报文，完成初始化后切换至 SyncWait 同步等待状态。
S2 采样收集（Collecting）
TimerTick 周期触发，节点向全网发送 TIME_REQ；采集四元时间戳T0​,T1​,T2​,T3​；设置超时阈值Timeout=2Dmax​+δ，超时未响应标记节点疑似故障；收集完成触发 CollectDone 事件，进入 Consensus 共识计算状态。
S3 时间共识计算（Consensus）
对全网采样集合排序，取中位数生成本轮基准Tc​；
广播 CONSENSUS_RESULT 带 ECDSA-P256 签名报文；
收到≥2f+1 节点确认后触发 ConsensusDone，切换至 Estimating 漂移估计状态。
S4 漂移与偏移估计（Estimating）
基于双向时延公式计算 RTT 与观测偏移θ^ij​；
滑动窗口最小二乘拟合，输出、；
估计完成触发 EstimateDone，进入 Running 正常运行状态。
S5 合成时钟输出（Running）
调用合成时钟公式生成统一同步时间，对外提供时序服务；持续缓存上一轮同步本地时钟Ci,last​用于下一轮 Δt 计算。
S6 闭环同步维护
下一轮 TimerTick 触发，节点切回 SyncWait，循环执行 S2~S5，持续闭环校正抑制时钟漂移。
S7 故障容错与恢复子算法
7.1 故障检测逻辑
连续 3 轮同步无响应触发 FaultDetect 事件，节点进入 Fault 故障状态；
全网广播带签名 FAULT_NOTIFY 报文，故障节点被逻辑剔除；
剩余正常节点仍满足n≥3f+1时，共识流程不受中断。
7.2 故障节点恢复流程（Recovering）
网络恢复触发 RecoverDone，进入 Recovering 恢复状态；
静默监听至少 2 个完整同步周期，提取全网、、；
中位数聚合计算自身目标基准Tc,target​，反向修正本地漂移 / 偏移模型；
广播 RECOVER_ANNOUNCE 签名报文；收到≥2f+1 节点 RECOVER_ACK 确认；
触发 AlignSyncDone，切回 SyncWait，完整参与后续同步循环。
五、节点有限状态机流转规则
状态集合：Init、SyncWait、Collecting、Consensus、Estimating、Running、Fault、Recovering、Stopped、Ext_Sync（外部单向校时）
Init → SyncWait：Start 事件（系统初始化完成）
SyncWait → Collecting：TimerTick（同步周期到达）
Collecting → Consensus：CollectDone（全部采样收集完成）
Consensus → Estimating：ConsensusDone（全网共识确认）
Estimating → Running：EstimateDone（漂移参数拟合完成）
Running → SyncWait：TimerTick（进入下一轮同步）
任意状态 → Fault：FaultDetect（超时、异常数据、网络中断）
Fault → Recovering：RecoverDone（网络链路恢复）
Recovering → SyncWait：AlignSyncDone（本地时钟对齐完成）
Running → Stopped：Stop 停机指令
Stopped/Fault → SyncWait：Reset 系统复位
SyncWait → Ext_Sync：ExternalTimeValid（单向外部时间输入有效）
Ext_Sync → SyncWait：ExtSyncDone（外部一次性校准完成）
六、报文安全算法（ECDSA-P256 签名）
所有交互报文附加 32 字节 ECDSA-P256 数字签名，保障防伪造、防篡改：
START_SYNC：同步启动指令签名，防止伪造同步触发；
CONSENSUS_RESULT：共识时间基准签名，保证全网基准可信；
FAULT_NOTIFY：故障节点通告签名，阻止恶意节点诬陷正常节点；
RECOVER_ANNOUNCE：故障恢复节点入网申请签名，校验节点合法身份。
标准报文通用字段
Magic (4B)=0x5453594E ("TSYN") | Version (1B) | Type (1B) | Round (4B) | NodeID (2B) | 业务载荷 | Signature (32B)
七、算法性能边界指标
漂移抑制能力：原生＞10ppm → 稳态≤0.1ppm；
全网最大相对误差：72h 长期运行≤±0.3ms；稳态抖动 1σ≤±0.05ms；
故障检测耗时：≤3.02s；故障恢复对齐耗时≤2.5s；
资源开销：单核 CPU 占用≤5%，内存≤64MB，单节点带宽≤120KB/s；
网络适应性：70% 背景流量下共识成功率≥99.99%，90% 流量≥99.95%；
时序特性：合成时钟全程严格单调，无时间跳变、无共识分裂。
八、算法核心创新点
无外部授时、无高精度硬件，纯软件分布式自闭环时间同步，适配物理隔离涉密场景；
中位数共识实现轻量化拜占庭容错，无需复杂 PBFT 多层消息交互；
滑动窗口线性回归持续闭环校正时钟漂移，解决廉价 RTC 长期发散问题；
分阶段共识 + 动态周期调优，平衡同步精度与网络开销；
完整故障检测、隔离、静默恢复流程，高鲁棒性适配工业不稳定网络；
单向外部校时扩展接口，兼顾完全隔离与可按需溯源 UTC 的混合场景。

十、算法适用边界说明
适用：内网完全隔离、禁止外联授时、无专用时钟硬件、要求统一可信时序用于审计 / 故障定位；
不适用：需要直接溯源 UTC、允许接入卫星授时、追求微秒级硬件同步精度场景；
扩容约束：新增节点后需保证总节点数满足n≥3f+1，否则容错能力下降。
